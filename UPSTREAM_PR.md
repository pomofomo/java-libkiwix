**Title:** Add bindings for the libzim writer (zim::writer::Creator)

---

Fixes #ISSUE (proposal and discussion of the API).

## What

New package `org.kiwix.libzim.writer` wrapping the libzim 9.8.2 writer, so ZIM
files can be created from Java/Kotlin:

| Java | libzim |
| --- | --- |
| `Creator` (`AutoCloseable`) | `zim::writer::Creator` |
| `StringItem` | `zim::writer::StringItem` |
| `FileItem` | `zim::writer::FileItem` |
| `Item` (abstract, package-private constructor) | `zim::writer::Item` |
| `Hint` (`COMPRESS`, `FRONT_ARTICLE`) | `zim::writer::HintKeys` |
| `Compression` (`NONE`, `ZSTD`) | `zim::Compression` |
| `ZimCreatorException` / `InvalidEntryException` / `CreatorStateException` | `zim::CreatorError` / `zim::InvalidEntry` / `zim::CreatorStateError` |

`Creator` exposes all of the C++ API: `configVerbose`, `configCompression`,
`configClusterSize`, `configIndexing`, `configNbWorkers` (chainable),
`startZimCreation`, `addItem`, `addMetadata` (text, or bytes + mimetype),
`addIllustration` (size, or the existing `IllustrationInfo`), `addRedirection`,
`addAlias` (with or without hints), `setMainPath`, `setUuid` and
`finishZimCreation`. The README has a Kotlin example.

## Design

- **Follows the existing binding pattern**: `nativeHandle` + `dispose()` +
  `finalize()`, one `.cpp` file per class using `macros.h`/`utils.h`, JNI headers
  generated by `buildHeaders` (new `getLibzimWriterFiles()`).
- **No JVM callbacks (threading).** `StringItem`/`FileItem` map to libzim's own
  items, so libzim's worker threads never call into the JVM: no
  `AttachCurrentThread`, no global references. The default HTML indexer
  indexes `text/html` items. The `Creator` is not thread-safe (documented);
  its methods are `synchronized` so misuse from several threads cannot crash
  the JVM.
- **Abort semantics.** `close()`/`dispose()` never finish the creation: closing
  an unfinished creator destroys the `zim::writer::Creator`, which removes the
  `.tmp` file. A `use {}`/try-with-resources block exiting with an exception
  therefore leaves no file behind (unlike python-libzim's `__exit__`).
- **State checks in Java.** `config*` after `startZimCreation()`, calls after
  `finishZimCreation()` and entry calls before `startZimCreation()` (which would
  dereference a null pointer in libzim) throw `IllegalStateException`. Invalid
  arguments (non-16-byte UUID, `nbWorkers < 1`, …) throw
  `IllegalArgumentException`, nulls throw `NullPointerException`.
- **Errors.** A new `CATCH_WRITER_EXCEPTION` maps `zim::InvalidEntry`,
  `zim::CreatorStateError`, other `zim::CreatorError`s (including `AsyncError`
  from workers) and any other native error to the exceptions above; a disposed
  handle maps to `IllegalStateException` as elsewhere.
- **UTF-8.** All strings are passed to native code as standard UTF-8 byte arrays
  (`String.getBytes(UTF_8)` → `jbyteArray`, new `jbytes2string` helper in
  `utils.h`) instead of `GetStringUTFChars`, whose *modified* UTF-8 breaks
  non-BMP characters (emoji) and NUL. The reader-side helper is unchanged (that
  would be a separate PR).

## Platforms

- **Linux JVM:** built into `libzim_wrapper.so`. The writer headers come from
  the Linux libzim tarball (now also copied to `build/include/libzim_linux` by
  `copyLibzimHeaderAndSoFiles`).
- **Android:** the libzim Android prebuilts are compiled with
  `LIBZIM_WITHOUT_WRITER` (no writer symbols or headers), so the writer `.cpp`
  files are only compiled for Linux; the Android build is unchanged and the
  AAR still builds for all ABIs. The Java classes are in the AAR but their
  native methods are not available on Android (see question 2 in the issue).

## Tests

`lib/src/test/org/kiwix/test/libzim/TestCreator.java` (JUnit 4, added to
`runTests`). Each test writes a ZIM in a temporary directory and reads it back
with `Archive`:

- `testCreateAndRead`: main page, `text/html` `StringItem`s, CSS, binary content,
  a PNG `FileItem`, redirections (with and without hints), an alias; mimetypes,
  content bytes, titles, front-article listing, checksum (`Archive.check()`).
- `testNoCompression`: `Compression.NONE`.
- `testMetadata`: standard metadata plus custom `X-Pack-Format`, `X-Pack-Themes`
  and `X-Pack-Sources` (JSON, `application/json`), via `getMetadata`,
  `getMetadataItem` and `getMetadataKeys`.
- `testIllustration`: `Illustration_48x48@1` via `getIllustrationItem(48)` and
  an `IllustrationInfo` (`48x48@2`).
- `testUuid`: `setUuid` round-trip via `Archive.getUuid()`; random by default.
- `testIndexing`: with `configIndexing(true, "eng")`, `Searcher` finds a word of a
  page, `SuggestionSearcher` finds a title, non-front articles are not suggested.
- `testUnicode`: CJK, accents and emoji in the file name, paths, titles, content
  and metadata. (Non-BMP paths/titles are checked in the raw dirents, since the
  reader's `String` API can't pass them.)
- `testAbortLeavesNoFile` / `testFinalizeAbortsCreation`: closing (explicitly,
  through try-with-resources with an exception, after an error, or by the
  finalizer) without finishing leaves neither `path` nor `path.tmp`.
- `testStateErrors`, `testInvalidArguments`: `IllegalStateException` /
  `IllegalArgumentException` / `NullPointerException` paths.
- `testLibzimErrors`: missing directory, duplicate path/metadata, alias to a
  missing entry, dangling redirection, missing file, disposed item.
- `testAsynchronousError`: a worker error (file truncated after `addItem`) is
  thrown by `finishZimCreation()`, then `CreatorStateException`; no file left.
- `testZimcheck`: runs `zimcheck -A` on a complete ZIM if a zimcheck linked to
  libzim ≥ 9 is in `PATH` (skipped otherwise; libzim 8's zimcheck rejects the
  ZIM 6.3 format written by libzim 9).

Tested on the Linux JVM (Java 17); `./gradlew buildHeaders build` builds the AAR
for all four Android ABIs, Android lint passes.
